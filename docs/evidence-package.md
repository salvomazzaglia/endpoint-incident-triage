# Evidence package

## Directory layout

```
case-<CASE-ID>-<STAMP>/
├── README.txt                 Sensitivity warning
├── metadata/
│   ├── case.json              Case and authorization metadata
│   ├── collection.json        Profile, platform, collector summary
│   ├── host-context.json      Host labels (may be redacted in reports)
│   └── tool.json              Tool name and version
├── artifacts/
│   ├── windows/               Normalized collector JSON
│   └── linux/
├── timeline/
│   └── timeline.jsonl         UTC-normalized events
├── findings/
│   └── findings.json          Heuristic findings
├── manifests/
│   ├── manifest.json          SHA-256 manifest
│   └── SHA256SUMS             Checksum list
├── custody/
│   └── custody.jsonl          Hash-chained ledger
├── logs/
│   └── collector-execution.jsonl
└── reports/                   Optional; generated by `report` command
```

## Sensitivity

Evidence packages may contain usernames, hostnames, IP addresses, process paths, and event metadata. Treat as **confidential** under organizational policy.

## Permissions

The orchestrator attempts owner-only permissions (`umask 077` on Linux collectors; restrictive modes on package directories where supported).

## Encryption

Version 1.0 ZIP output is **not encrypted**. Use organizational controls (encrypted volumes, access-controlled shares) for transfer and storage.

## Transfer and backup

- Verify before transfer: `endpoint-incident-triage verify --package ...`
- Copy manifest and custody ledger with artifacts
- Maintain separate backup per retention policy

## Retention and deletion

Follow organizational retention schedules. Secure deletion should remove all copies including temporary extraction directories from ZIP verification.

## Synthetic public example

`examples/synthetic-evidence-package/` is safe for documentation and CI. It is labeled **SYNTHETIC DEMONSTRATION DATA**.
